# ADR-0002: Per-page chapter markers

- Status: Accepted
- Date: 2026-07-05

## Context

A presentation video is naturally segmented into pages, but a plain MP4 gives
the viewer no way to jump between them. Players that understand MP4/QuickTime
chapters (QuickTime, IINA, VLC, and several web players; YouTube can derive
chapters from timestamps) can offer slide-level navigation if the container
carries chapter markers.

The mastering pipeline (ADR-0001) already produces exact per-page durations
(each segment is cut at `-t <probed audio duration>`) and already joins the
segments with the concat demuxer — the same place `voice-studio-mcp` attaches
m4b chapters via an ffmetadata file.

## Decision

Emit **one chapter marker per page**, on by default.

- **Mechanism.** Build an `;FFMETADATA1` file with one `[CHAPTER]` block per
  page (`TIMEBASE=1/1000`, `START`/`END` in ms, `title=`), write it inside the
  workspace, and pass it as the second input of the concat step with
  `-map 0 -map_metadata 1` (map all streams from the concat input, take global
  metadata — the chapters — from the ffmetadata input). This composes with the
  `-c copy` stream-copy concat; no re-encode.
- **Boundaries.** Cumulative sum of the per-page probed audio durations — the
  same values used for each segment's `-t`. No extra ffprobe calls.
- **Titles.** The manifest's optional `title` field; falls back to `Page N`.
  (`title` is deliberately distinct from the Phase-2 `caption`: a chapter title
  is a short nav label, a caption is on-screen subtitle text.)
- **Opt-out.** The `master` tool takes `chapters` (default `true`).

## Consequences

- **Free accuracy.** Because chapter times reuse the probed durations that
  drive `-t`, chapter boundaries coincide with page transitions. AAC frame /
  fps quantization can shift an actual boundary by well under a frame; invisible
  for navigation.
- **Metadata is trusted/server-written.** The ffmetadata file is generated by
  the server under `output/tmp/`, not agent-supplied, so it is handed to ffmpeg
  without the `VerifyRegular` pre-spawn check applied to agent assets.
- **New manifest field.** `title` joins the strict-decoded manifest schema;
  unknown keys still fail as `invalid_manifest`.
- **Container support only.** Chapters are metadata, not a burned-in visual;
  players without chapter support simply ignore them. On-screen page titles, if
  wanted, are a separate (Phase 2, caption-adjacent) feature.
