# ADR-0001: 2フェーズレンダリングパイプライン（ページ別セグメント → concat-copy）

- ステータス: Accepted
- 日付: 2026-07-05

## 背景

`master` ツールは N ページ（各ページ = 静止画 + 任意長のナレーション音声）を、
各ページが音声の長さちょうど表示される1本の MP4 にする必要がある。ffmpeg の
戦略は2つ:

1. **単一 filtergraph** — 2N 入力を1つの `ffmpeg` に渡し、ページ別の画像+音声
   サブストリームに対する `concat` フィルタを構築。
2. **2フェーズ** — ページごとに1セグメントをエンコードし、後で連結。

## 決定

**2フェーズ**パイプラインを採用する:

1. **ページ別セグメント。** 各ページで `ffmpeg -loop 1 -i 画像 -i 音声 -t
   <probe尺> -vf "scale=W:H:force_original_aspect_ratio=decrease,
   pad=W:H:(ow-iw)/2:(oh-ih)/2:<bg>,setsar=1,fps=F" -r F -c:v libx264 -crf …
   -tune stillimage -pix_fmt yuv420p -c:a aac -b:a … -ar …` → 均一に符号化された
   セグメント。
2. **連結。** concat demuxer リストを書き、`-c copy`（ストリームコピー、再
   エンコードなし）で連結。

ページ尺は `-shortest` に頼らず **ffprobe**（`format=duration`）で測定し `-t` に
渡す。これによりセグメント長が正確になり、正確な総尺を報告できる。各ページは
キャンバスに収まるようスケールし、**パッド**（レター/ピラーボックス）するので、
アスペクト比が混在しても歪まない。

## 帰結

- **均一性が必須。** ストリームコピー連結は、全セグメントがキャンバスサイズ・
  fps・ピクセルフォーマット・音声コーデック/レートを共有する場合のみ機能する。
  これらは `[video]` 設定で固定され `segmentArgs` で同一に適用される（ページ別
  ではない）。パイプライン全体の要となる不変条件。
- **単純で線形。** 処理はページ数に O(pages)。各ページが独立なので、将来の非同期/
  進捗（`check_job`）や並列エンコード拡張も容易。
- **テスト可能。** 引数ビルダは純関数で直接ユニットテスト。`Runner`
  インターフェースで ffmpeg/ffprobe をフェイクでき、`go test ./...` は
  ハーメティック。実 ffmpeg は手動検証。
- **コンテナが数ms長くなり得る。** AAC のプライミング/フレーム整列で最終尺が
  音声合計をわずかに超えることがある。ナレーション用途では許容。
- **字幕/トランジションはここではスコープ外。** `caption` 焼き込みと `fade`
  トランジション（Phase 2）は `segmentArgs` の拡張／ページ間フィルタパス追加で
  対応予定。字幕焼き込みは加えて CJK フォント同梱（Noto Sans JP / OFL）を要する。
  Phase 1 は全ページをハードカット・字幕なしで描画する。
