# ADR-0010: presentation-video スキルを同梱し、毎回のリリースに付ける

- Status: Accepted
- Date: 2026-11-04

## 背景

RFP は「上流のワークフロー用スキル」を、skills-series の別プロジェクトに
回していた。その間、このサーバーの使いこなしは mcp-tactics の
`references/media.md` が持っていた。組織の ADR-027 が両方を変えた。
mcp-tactics は v0.13.0 で制作系のサーバーを外した。ツール固有の使いこなしは、
ツールに同梱するスキルに置くことになった（nlink-jp/video-studio-mcp#1）。
その結果、エージェントをその案内へ導くものが無くなった。`get_usage` は呼び出しの
契約であって、良い動画の作り方は扱わない。

ADR-027 は、`get_usage` を超える使いこなしがあるときだけスキルを足す。
`media.md` がこのサーバーについて書いていたことは、ほぼすべて `get_usage` に
既にある。無いのは呼び出しの周りの仕事で、ナレーション付き動画の出来はそこで
決まる。

- 配信先を最初に決めること。画面の比率と字幕の種類がそこで決まる。
- ページ画像を画面の比率で描くこと。文字は画像生成の出力に描かせない。
- voice-studio で**ページごとに音声ファイルを 1 つ**作ること。voice-studio の
  `master` は 1 本の台本を 1 つのファイルにするので、資料にはページごとの台本が
  要る。行 id はすべての台本を通して重ならないようにする。どの台本も同じ
  `wav/<id>.wav` に書くため、id が重なると、あるページが別のページの声で
  黙って仕上がる。最後の行の間（`pause_after_ms`）が、次のページまでの間になる。
- マニフェストの `caption` は書き起こしではなく、ページの見出しとして書くこと。
  `fade` は章の区切りにだけ使うこと。
- 結果の数を依頼した内容と突き合わせること。見て確かめるのは、動画を再生できる
  利用者に任せること。

## 決定

1. **リポジトリ直下に `presentation-video/` を同梱する。** 形は ADR-027 の
   Decision 2 に従う。画像、ページごとの音声、マニフェスト、`master` という
   流れ全体を扱う。対話の台本とキャスティングは voice-studio の
   `multi-actor-narration` スキルに任せ、ここでは繰り返さない。
2. **`make test` は `go test ./...` の後に、組織のスキル検証
   （`tests/validate-skill.sh`、ADR-006）を走らせる。**
3. **`internal/tools/skill_test.go` がスキルとサーバーを両方向から照合する。**
   - 登録ツールにすべて触れていること。
   - backtick で囲んだ識別子が、すべてこのサーバーにあること。登録ツール、
     入力スキーマのプロパティ、`toolerr` のコード、サーバー自身の型の json
     タグのいずれか。
   - 廃止した `workspace_root` の綴りと `~/.video-studio` が無いこと。
   - マニフェストの例が `internal/manifest` で読めること。

   voice-studio の名前はここでは導けないので、持ち主を添えて列挙する。
   その一覧は、スキルが実際に使っている名前と一致していなければならない。
4. **毎回のリリースに `presentation-video-<版>.zip` を付ける。** zip の根は
   スキルのフォルダそのもの。`make package` が作り、`verify-release` は
   次のいずれかに当たるリリースを拒む。
   - zip が無い。
   - スキルの管理下のファイル以外を含む。
   - 管理下のファイルと中身が違う。

   voice-studio は、スキルが付いたリリースが 2 回、付かなかったリリースが
   17 回あった。それを必須にする仕組みが無かったためだ
   （voice-studio-mcp ADR-0015）。

## 結果

- ナレーション付き動画を頼まれたエージェントは、作業の順序と voice-studio との
  受け渡しを 1 か所で得られる。README は、呼び出し側ごとの導入方法を案内する。
- このサーバーのツール・引数・コード・マニフェストの項目の名前を変えると、
  スキルが追随するまでビルドが落ちる。voice-studio 側の名前の変更では落ちない。
  その一覧は手で保守する。
- スキルとサーバーは別々に入る。Homebrew とバイナリの zip には、サーバーしか
  入っていない。
