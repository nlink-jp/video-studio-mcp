# ADR-0006: ソフト mov_text トラックによるクローズドキャプション

- ステータス: Accepted
- 日付: 2026-07-06

## 背景

v0.1.0 は**焼き込み**字幕（ADR-0004）を出した: 常時表示ピクセルで、ミュートの
SNS 自動再生に最適。しかし焼き込みはトグル不可・選択不可で、スクリーンリーダーや
翻訳にもアクセスできない。**クローズドキャプション**（ソフト字幕）トラックは補完的
ニーズを満たす: 視聴者が ON/OFF し、プレイヤーが描画する —— しかも焼き込みと違い
こちら側にフォントが要らない。

手元の ffmpeg は libfreetype/libass 無しだが、MP4 ソフト字幕コーデック
**`mov_text`** は core エンコーダ（存在確認済）なので、ソフトトラックは mux のみ
—— テキスト描画不要。

## 決定

`master` に新フラグ **`soft_captions`**（既定 off）でソフトクローズドキャプション
トラックを追加。既存の `captions`（焼き込み）フラグとは**独立**。どちらか/両方を
有効化可能 —— v0.1.0 API への加算的・後方互換な変更（`captions` の意味は変えない）。

- **生成。** `buildSRT` が `caption` を持つページから SRT を描画。タイミングは
  チャプターと同じページ累積尺（caption 無しページはクロックを進めるがキュー無し）。
  SRT は `output/tmp/captions.srt` に書く。
- **Mux。** `concatArgs` は `metadataPath`（チャプター）と `subtitlePath` の両方を
  取るようになった。追加入力は concat 入力(0)の後に連番インデックスを受け、
  `-map` / `-map_metadata` / `-c:s mov_text` 引数はハードコードでなくそれらの
  インデックスから計算する —— よってチャプターと字幕は `-c copy` の1回の concat で
  正しく共存する。
- **空ケース。** どのページにも caption が無ければ SRT を書かず字幕入力も足さない
  （`soft_caption_cues = 0`）。

## 帰結

- **補完的な字幕戦略。** `captions` ＝ 常時表示ピクセル（ミュート自動再生）、
  `soft_captions` ＝ トグル可・選択可・アクセシブルなテキスト。両者は同じマニフェスト
  `caption` を参照。結果は `captions_burned` と `soft_caption_cues` を別々に報告。
- **新規依存なし・弱い ffmpeg でも動く。** `mov_text` は core、SRT は Go で作る平文。
- **`concatArgs` の一般化。** シグネチャに `subtitlePath` が増え、入力インデックスが
  動的に。チャプターのみの経路は挙動不変（字幕が無ければメタデータが入力1）。
- **タイミングはチャプターと共有。** AAC/fps 量子化の sub-frame 誤差はチャプターと
  同様、字幕では知覚不能。
- E2E 検証済: 2ページのデッキで `mov_text` ストリーム入り MP4 を生成し、抽出 SRT が
  マニフェスト字幕とタイミングに一致、チャプターマーカーとも併存。
