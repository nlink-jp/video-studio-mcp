# ADR-0003: インメモリジョブによる非同期レンダリング

- ステータス: Accepted
- 日付: 2026-07-06

## 背景

`master` は ffmpeg パイプライン全体（全ページ probe、ページごとにセグメント
エンコード、concat）を実行する。大きなデッキではクライアントのタイムアウトを
超えるほど MCP ツール呼び出しをブロックし得るうえ、待機中エージェントは進捗を
得られない。

## 決定

**オプトインの非同期モード**を追加。`master` に `async`（既定 `false`）を設ける:

- **`async: false`（既定）。** Phase 1 と同じ挙動: 同期レンダリングして完全な
  結果を返す。小さいデッキは1往復のまま。
- **`async: true`。** レンダをインメモリのバックグラウンドジョブとして投入し、即
  `{job_id, state: "running", pages}` を返す。新ツール `check_job` が `state`
  （`running`/`done`/`failed`）・粗い `progress`（フェーズ＋ページ done/total）・
  `done` 時は同期経路と同じ結果ペイロード（`failed` 時は構造化エラー）を返す。

設計上のポイント:

- **バリデーションは同期のまま。** マニフェストはツールハンドラで投入前に読み・
  パースするので `invalid_manifest` は即返る。重い ffmpeg 作業だけを背後に回し、
  素材/ffmpeg 失敗（`manifest_incomplete`・`ffmpeg_failed` 等）は `check_job` の
  エラーで表面化。
- **ジョブはサーバー寿命コンテキスト**（`Deps.JobCtx`）で走る（リクエスト
  コンテキストではない）—— さもないと `master` 呼び出しが返った瞬間にレンダ
  （と ffmpeg 子プロセス）がキャンセルされる。サーバー停止（SIGINT）時は
  コンテキストがキャンセルされ、進行中レンダを中断する。
- **インメモリ・非永続。** 完了ジョブ履歴は上限付きで evict。再起動後 `check_job`
  は `job_not_found` を返し `master` 再実行を案内（安全: 同じエージェント用意
  ワークスペースから再描画）。`voice-studio-mcp` のジョブモデルに倣い、クラッシュ
  生存だけが目的の永続層を避ける。
- **1ジョブ=1レンダ。** `voice-studio-mcp` の行単位アイテムジョブと異なり、動画
  レンダは逐次パイプラインなので、ジョブは `master.Build` 全体を包む。`internal/job`
  マネージャは相応に単純（汎用 `RunFunc` ＋ 進捗コールバック、`master` パッケージ
  から疎結合）。

## 帰結

- 長尺レンダがクライアントタイムアウトを招かず、エージェントは進捗を表示できる。
- `master` の応答形が2種（同期＝結果オブジェクト、非同期＝`{job_id,…}`）。
  クライアントは `job_id` の有無で分岐。`get_usage` マニュアルが両方を記述。
- 進捗は粗い（ページ単位＋フェーズ）。より細かい進捗（ffmpeg 自身のフレーム
  カウンタ）は将来 ffmpeg `-progress` パースで可能だが、Phase 2 ではパース面の
  コストに見合わないと判断。
- 新規依存なし。`internal/job` は pure Go で完全にハーメティックにテスト済み。
